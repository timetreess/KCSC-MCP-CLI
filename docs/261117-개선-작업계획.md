# KCSC Standards MCP/CLI 개선 작업 계획

## 확인된 상태와 결정

- GitHub 저장소는 `timetreess/KCSC-MCP-CLI`다. `timetreess/kds`는 현재 원격 주소와 다르다.
- GitHub에는 `v1.0.0` 태그와 릴리스가 있다. 릴리스 날짜는 2026-05-05다. `CHANGELOG.md`의 2026-04-30 표기는 릴리스 기록과 맞춰야 한다.
- `kcsc-standards-mcp`는 npm에 게시되지 않았다. 게시 전까지 README는 저장소에서 직접 설치하는 방법을 안내한다.
- README의 주 독자는 KCSC 기준을 찾는 실무자로 정한다. 개발 안내는 CONTRIBUTING 및 별도 문서에 둔다.
- `check_applicability`는 제거하거나 실험 기능으로 숨기지 않고, 오탐을 줄이는 방향으로 개선한다.
- `get_standard`의 기본 응답 등 공개 인터페이스 변경은 허용한다. 이미 `v1.0.0`이 공개되어 있으므로 호환성을 깨는 변경은 `2.0.0`으로 릴리스한다.
- `KCSC_API_KEY` 외 기존 환경변수 별칭도 지원한다. 별칭이 든 `.env`는 명시적으로 지정한 파일이나 저장소 자체 설정 파일에서만 읽고, 실행 작업 폴더의 임의 `.env`는 자동으로 읽지 않는다.
- README 예시 출력을 위해 KCSC OpenAPI 검색을 읽기 전용으로 한 번 호출하는 것을 승인받았다. 호출은 키가 이미 설정된 경우에만 하고 키를 로그나 문서에 남기지 않는다.

## 기준선

2026-11-17에 `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, `npm run verify:package`를 실행했다. 타입체크와 빌드가 통과했고, 테스트 16개 파일의 123개 케이스와 패키지 검증도 통과했다.

`npm audit`에서는 프로덕션 의존성에서 취약점 5건(중간 3건, 높음 2건)이 확인됐다. MCP SDK의 전이 의존성인 `@hono/node-server`, `hono`, `body-parser`, `fast-uri`에는 호환 범위 내 수정 버전이 있다. 직접 의존성 `zod`는 고위험 취약점 수정에 4.x 업그레이드가 필요하다. 확인한 MCP SDK 1.32.1은 Zod 3.25와 4.x를 모두 지원하므로, Zod 4 전환을 회귀 테스트와 함께 2.0.0 작업에 포함한다.

## 현재 진행

- 설치 안내, 저장소 링크, 릴리스 날짜를 바로잡고 PRD를 `docs/PRD.md`로 옮겼다. 내부 검증 작업 기록은 사용자 문서에서 분리했다.
- 응답 본문 읽기까지 제한시간·취소를 적용하고, `.env`를 저장소 설정 또는 `KCSC_ENV_FILE`로 제한했다.
- 검색 순위, 적용성 오탐, 분류경로 수집, 조항 후보 수와 결과 수 구분, `latest_check` 문구를 개선했다.
- MCP 응답 크기와 취소 전달, CLI 도움말·버전·JSON·옵션 검증을 개선했다.
- 현재 변경 검증은 타입체크, 테스트 140개, 빌드, 패키지 설치·실행 검증까지 통과했다.
- `npm audit fix`로 전이 취약점은 갱신했다. Zod 4 전환과 린트·CI·타입 경계 정리는 남아 있다.
- 로컬 환경에 KCSC API 키가 없어 승인된 읽기 전용 실조회는 아직 하지 않았다. 예시 출력은 fixture 기반임을 표시했다.

## 진행 순서

### 1. 기준선과 작업 분리

기존 사용자 파일인 `docs/261117 리뷰.md`는 수정하거나 커밋하지 않는다. 기준선은 위 기록과 같으며, 실패가 나오면 새 변경과 기존 실패를 구분한다.

### 2. 설치 경로와 문서

- README, `package.json`, CONTRIBUTING, SECURITY, AGENTS의 저장소 링크를 현재 원격 주소로 통일한다.
- npm 게시 전 설치 절차를 `git clone`, `npm ci`, `npm run build` 순서로 안내한다. MCP 설정에는 빌드된 서버 경로와 `KCSC_API_KEY` 설정 예시를 둔다.
- README 앞부분에 CLI 검색 예시와 확인된 출력 예시를 추가한다. 실조회가 불가능하면 예시 데이터임을 표시한다.
- 요청 제한시간, 내부 API 동작, 진단용 라이브러리 인터페이스 설명은 별도 문서로 옮기고 사용자에게 필요한 검색 범위와 결과 해석은 README에 남긴다.
- `docs/improvement-plan.md`와 루트 PRD는 공개 사용자에게 필요한 설계 내용만 남기도록 정리한다. 라이브 호출 작업 기록은 공개 문서에서 제거한다.
- `CHANGELOG.md`의 `v1.0.0` 날짜를 GitHub 릴리스 날짜와 맞춘다. npm 게시나 GitHub 릴리스는 이번 작업에서 실행하지 않는다.

완료 기준: 새 사용자가 README만 보고 로컬 CLI와 MCP 서버를 설정할 수 있고, 안내된 링크가 모두 현재 저장소를 가리킨다.

### 3. 요청 제한시간, 키 설정, 출처 링크

- KCSC 응답 헤더를 받은 뒤 본문 읽기가 멈춰도 요청 제한시간과 호출자 취소가 동작하게 한다. 타이머와 이벤트 리스너는 모든 완료·실패 경로에서 정리한다.
- 기존 키 별칭을 유지하면서 `.env` 탐색 위치를 명확히 한다. 우선순위와 `KCSC_ENV_FILE` 같은 명시적 파일 지정 방식을 정하고, 설정을 요청마다 다시 읽지 않게 한다.
- `sourceUrl`이 사람용 출처로 열리는지 확인한다. API 주소만 제공되는 경우 API endpoint라고 명시하고, 확인되지 않은 웹 주소를 만들어 넣지 않는다.

검증: 본문 읽기 미완료, 취소, 지정된 `.env`, 다른 작업 폴더의 무관한 `SERVICE_KEY`를 각각 주입한 테스트로 동작을 확인한다.

### 4. 검색과 적용성 정확도

- 보고서에 제시된 색상·상수 `k` 문장을 적용성 회귀 테스트로 추가한다. `상수도`나 `기초` 키워드가 단어 일부와 우연히 겹쳤다는 이유만으로 적용성을 판정하지 않게 한다.
- 기준 코드·기준명·분류경로·조항 제목과 본문을 구분해 근거 강도를 조정한다. 본문 키워드는 단순 부분 문자열 한 번 일치만으로 강한 근거가 되지 않게 한다.
- `parentPath`를 실제 API 데이터에서 구성하는 경로를 확인하고, 분류경로 근거가 수집되지 않는 원인을 고친다.
- 검색어 불용어를 추가하되 기준명 일치에 더 높은 가중치를 둔다. 정확한 기준 코드 질의는 일반 토큰 매칭으로 다른 기준을 끌어오지 않게 한다.
- `find_clause`의 `limit`과 후보 문서 열람 수를 분리한다. 새 입력이 필요하면 MCP 스키마와 CLI 설명도 함께 갱신한다.
- `latest_check`가 metadata 존재 확인만 하는 동작과 결과 문구를 일치시킨다. 최신성 검증이나 프로젝트 적용성으로 오해할 표현은 고친다.

완료 기준: 보고서의 오탐 재현이 차단되고 기존 검색 평가 10건이 유지된다. 기준코드 질의와 `find_clause` 제한값 동작은 회귀 테스트로 고정한다.

### 5. MCP 응답과 CLI 사용성

- `get_standard`에서 HTML을 기본 응답에서 제외하고 요청 시에만 포함한다. 긴 문서의 조항 필터 또는 목차 모드도 제공한다.
- MCP의 텍스트 콘텐츠에 전체 구조화 JSON을 중복으로 담지 않는다. 큰 fixture를 사용해 실제 출력 크기를 비교한다.
- MCP 요청 취소 신호를 모든 관련 서비스 호출까지 연결한다. 사용하지 않는 `specialty_type` 입력은 제거하거나 표준 코드와의 일치 여부를 검증한다.
- CLI에 명령별 `--help`, `--version`, `--json`을 추가하고, 알 수 없는 옵션은 오류로 종료한다.

완료 기준: 출력 스키마 테스트, 취소 테스트, CLI 옵션 테스트, 패키지 설치 후 CLI/MCP 검증이 통과한다. 호환성 파괴 변경은 `2.0.0` 변경으로 기록한다.

### 6. 유지보수 개선과 최종 검증

- 취약한 전이 의존성을 호환 범위 내 수정 버전으로 갱신한다. `zod`는 SDK의 지원을 확인한 뒤 4.x로 올리고 MCP 스키마와 패키지 계약 테스트를 실행한다.
- `as any`, 미처리 예외 등 실제 코드 규칙 위반을 검사할 ESLint 구성을 CI에 추가한다. 전체 파일을 불필요하게 재포맷하지 않는다.
- 여러 파일에 나뉜 어휘와 전문시방서 유형 목록은 실제 중복으로 인한 드리프트를 줄이는 범위에서 통합한다.
- API 응답 타입과 도메인 결과 타입, 중복 Zod enum, 테스트까지 포함하는 빌드 설정은 사용처를 확인한 뒤 분리한다.
- MCP 서버 버전의 하드코딩과 `package.json` 버전 불일치를 제거한다. CI는 지원 최소 버전과 현재 LTS Node에서 확인한다.

최종 검증은 다음을 실행한다.

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run verify:package
```

라이브 검증은 승인된 README 예시 검색 1회로 제한한다. 실제 API 키는 출력, 문서, 테스트 fixture, 커밋에 넣지 않는다. npm 게시와 GitHub push는 별도 승인 전까지 하지 않는다.
