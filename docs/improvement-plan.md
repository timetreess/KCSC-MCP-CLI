# 리뷰 개선 작업 현황

관련 변경을 묶어서 구현하고, 각 묶음의 검증과 로컬 체크포인트 이후 사용자 확인을 받아 다음 묶음을 진행한다. 테스트는 특별한 허용이 없는 한 가짜 응답을 사용하고 KCSC 실서버를 호출하지 않는다.

## 1. 조회 실패 처리 — 완료

- [x] 정상 빈 응답과 잘못된 API 응답을 구분한다. 잘못된 항목을 조용히 제거하지 않는다.
- [x] 상세 응답의 기준 유형·코드가 요청과 일치하는지 검증한다.
- [x] HTTP 상태 설명과 JSON 파싱 예외의 원문을 외부 오류 메시지에 노출하지 않는다.
- [x] 조항 후보 상세 조회가 모두 실패하면 CLI/MCP 오류로 알린다.
- [x] 일부 조회만 실패하면 성공한 근거와 실패 기준·사유를 함께 제공한다. 근거가 0건이어도 실패 내역을 보존한다.
- [x] 기존 배열 API의 정상 반환 형식은 유지하되 불완전한 결과를 숨기지 않는다.
- [x] 타입 검사·전체 테스트·빌드·최종 diff 검증을 완료한다.

검증: API 응답 파서, 조항 검색, CLI, 실제 MCP in-memory 프로토콜의 회귀 테스트. 전체 테스트 74개, 타입 검사, 빌드 통과. 기존 사용자 변경은 체크포인트에서 제외한다.

## 2. 근거 무결성 — 완료

- [x] 기준명·개정일이 없으면 `원문 직접 근거`를 쓰지 않고 `관련 조항 추론`으로 낮춘다. 빠진 항목은 `evidenceGaps`로 알린다.
- [x] API에 기준명이 없으면 기준코드를 기준명처럼 채우지 않고 누락 사실로 남긴다.
- [x] 조항 근거의 신뢰도도 문서 근거 무결성을 따르도록 한다.
- [x] 위첨자·아래첨자를 `^`/`_`로 보존하고, 이미지는 `alt` 유무에 따라 `[그림: 설명]` 또는 `[그림]`으로 남긴다.
- [x] CLI의 30개 조항 제한을 제거해 조용한 본문 누락을 없애고 조항 수를 표시한다.
- [x] 타입 검사·전체 테스트·빌드와 CLI/MCP 공통 core 경로 재현을 확인한다.

검증: 전체 테스트 81개 통과. 빌드 산출물에서 `10<sup>-6</sup>` → `10^-6`, 이미지 `[그림: …]` 보존, 불완전 응답의 신뢰도 하향(`관련 조항 추론`)과 `evidenceGaps`를 직접 확인했다. 표·엔티티·script 제거의 기존 동작은 그대로 유지된다.

주의: 라이브 KCSC 응답에 본문이 실제로 비어 있는 조항이 존재한다(`- 조항번호: 본문` / `내용 없음`). 이는 API 원본 데이터 문제이며 이번 작업 범위가 아니다.

## 3. 검색 품질 — 완료

- [x] 후보 탐색에 동의어 확장 항목을 함께 넣어, 기준명이 영어인 경우에도 후보가 잡히게 한다.
- [x] `searchScope`와 `searchedCodes`로 실제 열람한 문서를 알려 준다. 후보를 찾지 못하면 `unresolved`로 보고 근거 부재로 해석되지 않게 한다.
- [x] CLI와 MCP에 재시도 안내(`scopeNote`)를 제공한다.
- [x] 한 글자 프로젝트 키워드(`항`, `댐`)를 제거해 `일반사항`이 항만 기준으로 분류되는 오탐을 없앤다.
- [x] 적용성 판단에 사용된 키워드와 근거 위치를 `evidence`로 반환한다.
- [x] 대표 업무 질의 10건을 오프라인 평가로 고정하고 metadata 도달 가능 / 본문 전용 두 부류로 구분한다.
- [x] 타입 검사·전체 테스트·빌드와 CLI/MCP 실제 경로 재현을 확인한다.

검증: 전체 테스트 102개 통과. 평가 10건 중 9건은 기준번호 없이 근거를 찾고, 1건(본문 전용 표현)은 `unresolved`로 정확히 보고합니다. 같은 질의에 기준번호를 주면 `standard` 범위로 근거 1건을 찾습니다. `일반사항` → port 미매칭, `방파제` → port 매칭을 실경로에서 확인했습니다.

한계: 후보 탐색이 metadata 랭킹에 의존하므로 본문 전용 표현은 기준번호 없이는 도달할 수 없습니다. 이는 구조적 한계이며, `unresolved`로 숨기지 않고 드러내는 것으로 처리했습니다. 본문 전체 색인은 이번 범위가 아니며 도입 전 누락률 기준이 필요합니다.

## 4. MCP·요청 안정성 — 완료

- [x] 7개 도구 출력 스키마를 실제 결과 구조로 정의하고 알 수 없는 필드를 거부한다.
- [x] 기본 15초 요청 제한시간과 호출자 취소 신호를 추가한다. 주입 `fetch`가 abort signal을 무시해도 경합(race)으로 동작한다.
- [x] 이미 취소된 요청은 전송 전에 실패하고, 오류에 `reason`(http/timeout/cancelled/transport/invalid-json/invalid-response)을 붙인다.
- [x] 진행 중인 CodeList 요청을 공유해 동시 조회 중복을 제거한다. TTL 캐시는 도입하지 않는다.
- [x] 엄격한 스키마가 드러낸 실제 결함 두 건(sectionPath 배열 구멍, check_applicability 결과 구조)을 함께 고친다.
- [x] 타입 검사·전체 테스트·빌드와 MCP in-memory 실경로 12건 검증을 확인한다.

검증: 전체 테스트 117개 통과. 동일 검색 CodeList 호출 2회 → 1회, 동시 검색+존재확인 2회 → 1회, 순차 검색은 2회(오래된 캐시 없음). 제한시간은 200ms 설정에서 213ms에 `timeout`, 호출자 취소는 `cancelled`로 종료됨을 빌드 산출물에서 확인했습니다. 실경로 12건 모두 자체 출력 스키마를 통과합니다.

발견한 추가 결함: `updatePath`가 첫 조항이 level 2 이상이면 희소 배열을 만들어 `sectionPath`에 빈 항목이 들어가 있었습니다(CLI에서 `목차경로:  > 1.1 목적` 형태로 노출). 스키마 검증이 이를 `undefined` 타입 오류로 잡아냈고, 인덱스 클램프로 수정했습니다.

한계: 제한시간은 요청 단위이며 `find_clause`가 여러 후보를 순차 조회하므로 전체 작업 시간은 후보 수에 비례합니다. 이번 범위에서 전체 작업 제한시간은 도입하지 않았습니다.
