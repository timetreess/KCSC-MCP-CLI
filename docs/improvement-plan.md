# 리뷰 개선 작업 현황

관련 변경을 묶어서 구현하고, 각 묶음의 검증과 로컬 체크포인트 이후 사용자 확인을 받아 다음 묶음을 진행한다. 테스트는 특별한 허용이 없는 한 가짜 응답을 사용하고 KCSC 실서버를 호출하지 않는다.

## 1. 조회 실패 처리 — 완료

- [x] 정상 빈 응답과 잘못된 API 응답을 구분한다. 잘못된 항목을 조용히 제거하지 않는다.
- [x] 상세 응답의 기준 유형·코드가 요청과 일치하는지 검증한다.
- [x] HTTP 상태 설명과 JSON 파싱 예외의 원문을 외부 오류 메시지에 노출하지 않는다.
- [x] 조항 후보 상세 조회가 모두 실패하면 CLI/MCP 오류로 알린다.
- [x] 일부 조회만 실패하면 성공한 근거와 실패 기준·사유를 함께 제공한다. 근거가 0건이어도 실패 내역을 보존한다.
- [x] 기존 배열 API의 정상 반환 형식은 유지하되 불완전한 결과를 숨기지 않는다.
- [x] 타입 검사·전체 테스트·빌드·최종 diff 검증을 완료한다.

검증: API 응답 파서, 조항 검색, CLI, 실제 MCP in-memory 프로토콜의 회귀 테스트. 전체 테스트 74개, 타입 검사, 빌드 통과. 기존 사용자 변경은 체크포인트에서 제외한다.

## 2. 근거 무결성 — 대기

- [ ] 기준명·날짜·조항 경로 등 근거 정보의 완전성과 신뢰도 라벨을 일치시킨다.
- [ ] 수식·첨자·이미지·표 변환의 의미 손실을 보존하거나 명시적으로 알린다.
- [ ] CLI의 30개 섹션 제한으로 발생하는 조용한 본문 누락을 없앤다.

검증: 누락 정보의 신뢰도 하향, 대표 수식·표 fixture, 31개 이상 섹션의 CLI 출력.

## 3. 검색 품질 — 대기

- [ ] 기준번호 없는 조항 검색의 후보 발견 문제를 개선한다.
- [ ] 적용성 판단의 단일 음절 등 과도한 부분 일치를 제거하고 실제 근거 위치를 제공한다.
- [ ] 대표 업무 질의와 기대 문서를 묶은 오프라인 평가로 개선 전후 누락·오탐을 비교한다.

## 4. MCP·요청 안정성 — 대기

- [ ] 실제 출력 구조를 반영하는 MCP 스키마로 필수 필드와 타입을 검증한다.
- [ ] 외부 요청에 제한시간과 취소 신호를 전달한다.
- [ ] 동시 KDS/KCS 검색에서 동일 metadata snapshot을 공유한다. 장기 캐시는 측정 없이 도입하지 않는다.

검증: 잘못된 출력 거부, 제한시간·취소 테스트, 동일 검색의 CodeList 호출 2회→1회 확인.

## 5. 배포·의존성 — 대기

- [ ] npm 패키지의 실제 CLI와 stdio 진입점을 오프라인으로 검증한다.
- [ ] 보안 경고의 사용 경로를 검토하고 호환되는 의존성·lockfile 갱신을 적용한다.
- [ ] CI에 배포 실행 경로 검증을 포함한다.

검증: 패키지 실행 smoke test, 타입 검사·전체 테스트·빌드, 보안 audit의 잔여 경고와 도달 가능성 보고.
